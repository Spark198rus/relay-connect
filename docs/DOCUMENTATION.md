# Relay Connect — документация и FAQ

Актуально на 6 ноября 2026.

## Что это и зачем

Relay Connect возвращает доступ к VPN на зарубежном сервере, у которого заблокирован IPv4. Клиенты подключаются к российскому VPS по IPv4, а тот пересылает трафик на IPv6 зарубежного сервера.

```
                 IPv4                     IPv6
 Клиент Amnezia ──────► RU-сервер (realm) ──────► Зарубежный VPS ──────► Интернет
 телефон или ПК         IPv4 :порт → IPv6         Amnezia в docker       выход из DE
 в России                                          IPv6 :порт
       │                                                ▲
       └──────── прямой путь на IPv4 заблокирован ──────┘ ✕
```

RU-сервер принимает клиентов по IPv4 и пересылает их пакеты на IPv6 зарубежного сервера на тот же порт. Заблокированный IPv4 зарубежного сервера больше не нужен.

- **Почему это работает.** Блокировка привязана к конкретному IPv4-адресу. Российский IPv4 не заблокирован, а IPv6 зарубежного сервера в списке блокировок обычно нет.
- **Что ставится.** На RU-сервер ставится realm, маленький пересыльщик TCP/UDP. Пакеты AmneziaWG он пересылает как есть и ничего не расшифровывает.
- **Почему не 3x-ui, как в видео.** Схема на VLESS требует перевести всех клиентов на другой протокол. Здесь Amnezia, ключи и протокол остаются прежними, в клиенте меняется только адрес сервера.
- **Что нужно от тебя.** IPv4 российского сервера, IPv6 зарубежного и root-пароли от обоих. Всё остальное программа делает сама.

## Требования

Главное условие: IPv6 должен работать на обоих серверах. Без IPv6 на российском VPS схема не заработает.

| | Российский VPS (вход) | Зарубежный VPS (выход) |
| --- | --- | --- |
| IPv4 | нужен, к нему подключаются клиенты | заблокирован, не используется |
| IPv6 | нужен, через него идёт трафик на зарубежный | нужен, публичный (global) |
| Доступ | root и пароль по SSH | root и пароль по SSH |
| ОС | Linux с systemd: Ubuntu, Debian и похожие | та, где уже стоит Amnezia |
| Процессор | x86_64 или aarch64 (ARM) | x86_64 или aarch64, если понадобится мост |
| Ресурсы | хватит самого дешёвого тарифа, важнее канал и лимит трафика | как сейчас |

- **ПК, с которого запускаешь программу:** Windows 10 или 11. IPv6 на ПК не нужен: к зарубежному серверу программа ходит через российский.
- **На зарубежном сервере Amnezia должна быть установлена через приложение,** то есть в docker-контейнерах `amnezia-*`. Иначе порты придётся вписать вручную.
- **При выборе российского VPS спроси у хостера про IPv6 до оплаты.** Многие выдают его только по запросу или за отдельную галочку в панели.

## Установка и запуск

Программа есть для Windows, macOS, Linux и Android, функции везде одинаковые. На Windows проще всего взять готовый `RelayConnect.exe` из папки `dist`: устанавливать ничего не нужно.

| Система | Файл | Как запустить |
| --- | --- | --- |
| Windows 10/11 | `RelayConnect-windows.exe` (или `dist\RelayConnect.exe`) | двойной клик |
| macOS, Apple Silicon | `RelayConnect-macos-arm64.zip` | распаковать, правый клик по `RelayConnect.app` → «Открыть»; если macOS не даёт: `xattr -dr com.apple.quarantine RelayConnect.app` |
| macOS, Intel | исходники | `pip3 install -r requirements.txt`, затем `python3 app.py` |
| Linux x86_64 | `RelayConnect-linux-x86_64.tar.gz` | `tar xzf RelayConnect-linux-x86_64.tar.gz && ./RelayConnect`, нужен графический сеанс |
| Android 7+, 64-bit | `RelayConnect-android.apk` | скопировать на телефон, открыть, разрешить установку из неизвестных источников |

Все файлы собирает GitHub Actions: при каждом пуше они появляются в артефактах запуска, а при пуше тега `v1.0.0` в релизе. Вручную настольные версии собираются скриптом `build.bat` (Windows) или `build.sh` (macOS, Linux).

**Особенности Android-версии.** Разделы «Настройка» и «Ключ клиента» переключаются кнопками сверху. Ключ клиента вставляется текстом из буфера обмена, открыть файл нельзя. Результат копируется кнопкой «Копировать» или отправляется кнопкой «Поделиться». Пока идёт настройка, не сворачивай приложение: Android может оборвать SSH-соединение фонового приложения.

Для сборки и запуска из исходников нужен Python 3.10 или новее с tkinter. На Ubuntu и Debian его ставит `sudo apt install python3-tk`, на macOS tkinter уже входит в Python с python.org.

- **Windows SmartScreen** может предупредить о неизвестном издателе: файл не подписан. Нажми «Подробнее» → «Выполнить в любом случае».
- **Антивирус** иногда ругается на файлы, собранные PyInstaller. Если не доверяешь .exe, запускай `python app.py`: код тот же.
- **Настройки формы** (адреса, порты, логины) запоминаются в `%APPDATA%\relay-connect\settings.json`. Пароли не сохраняются нигде.

## Пошаговая инструкция

Настройка занимает три кнопки: «Проверить», «Настроить» и «Преобразовать» на вкладке конфига. В логе зелёные строки ✔ означают успех, жёлтые ⚠ предупреждение, красные ✖ ошибку.

1. **Узнай адреса.** IPv4 российского сервера и IPv6 зарубежного есть в панели хостера. Ещё IPv6 можно посмотреть на самом сервере командой `ip -6 addr show scope global`: нужен адрес после `inet6`, без `/64`.
2. **Заполни вкладку «Настройка».** Адреса, SSH-порты (обычно 22), логин `root` и пароли. Поле «Порты» оставь пустым: программа сама найдёт порты контейнеров Amnezia.
3. **Нажми «1. Проверить».** На серверах ничего не меняется. Программа проверит пароли, IPv6 на обоих серверах, порты Amnezia и то, что на RU-сервере эти порты свободны. Пока в логе есть красные строки, дальше не иди: смотри FAQ ниже.
4. **Нажми «2. Настроить».** Занимает от 30 секунд до пары минут. В конце программа прогонит тестовый пакет насквозь и покажет окно «Готово» с новым адресом для клиентов.
5. **Возьми старый ключ в Amnezia.** Открой сервер → «Поделиться» → «Ключ Amnezia» (`vpn://…`) или «Нативный формат AmneziaWG» (файл `.conf`). Удобнее сделать там, где сервер уже добавлен.
6. **Переделай ключ.** Вкладка «Конфиг клиента»: вставь ключ или открой файл, проверь, что в «Новый адрес» стоит IPv4 RU-сервера, нажми «Преобразовать». Поле «Старый адрес» можно оставить пустым.
7. **Импортируй результат в Amnezia как новое подключение** и подключись. Пользуйся им на том же устройстве вместо старого, а старое подключение после проверки удали. Это тот же ключ AmneziaWG с другим адресом, поэтому на двух устройствах одновременно он не работает: устройства будут выбивать друг друга. Для другого устройства создай в Amnezia отдельного пользователя и его ключ тоже прогони через «Конфиг клиента».

Проверка, что трафик идёт через зарубежный сервер: после подключения открой любой сайт «мой IP». Должен показаться немецкий адрес, а не адрес RU-сервера.

## Выдача ключей

Новые ключи выдаются на вкладке «Ключи», без управления сервером из приложения Amnezia. Программа заходит на зарубежный сервер через RU-сервер, поэтому заблокированный IPv4 ей не нужен. Данные серверов берутся с вкладки «Настройка».

| | Обычный ключ | Админский ключ |
| --- | --- | --- |
| Для чего | подключить новое устройство | управлять сервером из приложения Amnezia: создавать пользователей, делиться ключами |
| Что делает программа | добавляет нового пользователя в AmneziaWG на сервере, его имя видно в списке пользователей Amnezia | собирает ключ полного доступа с SSH-доступом к серверу через RU-сервер |
| Адрес внутри | IPv4 RU-сервера и порт Amnezia | IPv4 RU-сервера и порт SSH-проброса (по умолчанию 2222) |
| Формат | `vpn://…` одной строкой или файл `.conf` | `vpn://…` |
| Можно пересылать | да, это обычный ключ на одно устройство | нет: внутри root-пароль зарубежного сервера |

**Обычный ключ.** Впиши имя пользователя, например «Телефон мамы», и нажми «Создать обычный ключ». Скопируй ключ `vpn://…` и на устройстве в Amnezia выбери «Добавить» → «Вставить ключ». Перед изменением программа сохраняет копию конфига сервера, и если AmneziaWG не примет нового пользователя, всё вернётся как было.

**Админский ключ.** Сначала на вкладке «Настройка» проверь, что в поле «SSH-проброс» стоит порт (по умолчанию 2222), и нажми «Настроить»: RU-сервер начнёт пересылать этот порт на SSH зарубежного сервера. Потом нажми «Создать админский ключ» и импортируй его в своё приложение Amnezia. После этого приложение снова управляет сервером, и ключи, которые оно создаёт через «Поделиться», сразу будут с адресом RU-сервера. При первом подключении приложение само создаст себе пользователя на сервере, так делает Amnezia с любым админским ключом.

В админский ключ попадает только протокол AmneziaWG. Другие протоколы на сервере, если они есть, приложение через такой ключ не увидит.

## Что программа меняет на серверах

На RU-сервер ставится relay. На зарубежном сервере Amnezia не трогается: программа только открывает порты и, если нужно, ставит мост.

| Сервер | Что | Где | Зачем |
| --- | --- | --- | --- |
| RU | realm v2.9.6 | `/usr/local/bin/realm` | пересыльщик TCP/UDP |
| RU | конфиги relay | `/etc/relay-connect/udp.toml`, `tcp.toml` | какие порты куда пересылать |
| RU | сервисы `relay-connect@udp`, `relay-connect@tcp` | `/etc/systemd/system/relay-connect@.service` | автозапуск и перезапуск через 3 секунды при падении |
| RU | буферы UDP | `/etc/sysctl.d/99-relay-connect.conf` | меньше потерь на быстром трафике |
| RU | правила фаервола IPv4 | ufw, firewalld или iptables | открыть порты для клиентов, только если фаервол включён |
| Зарубежный | правила фаервола IPv6 | ufw, firewalld или ip6tables | пустить трафик на порты Amnezia по IPv6 |
| Зарубежный | мост `relay-connect@bridge-udp` / `bridge-tcp` | те же пути, что на RU | только если Amnezia не слушает IPv6: передаёт `[IPv6]:порт` на `127.0.0.1:порт` |
| Зарубежный | tcpdump | через apt | для сквозной проверки UDP, если его не было |

Сервисы relay работают не от root, а от временного системного пользователя (DynamicUser). У них есть только право занимать порты. Повторное нажатие «Настроить» безопасно: конфиги перезаписываются, дубли правил не создаются.

**Сеть Docker и Amnezia программа не трогает.** Фаервол firewalld она не перезагружает: такая перезагрузка может сбросить правила Docker и отрезать контейнеры от сети. Если фаервол настроен напрямую через iptables или ip6tables, правила программы восстанавливает после перезагрузки отдельный сервис `relay-connect-fw-v4` или `relay-connect-fw-v6`. Он добавляет только свои правила из `/etc/relay-connect/`, а правила Docker никуда не сохраняются.

**SSH-проброс** (если в поле «SSH-проброс» указан порт) добавляет на RU-сервере ещё одну пересылку: TCP-порт, по умолчанию 2222, ведёт на SSH зарубежного сервера. Он нужен только для админского ключа. Через этот порт к зарубежному серверу можно подключиться по SSH с любого адреса, поэтому root-пароль должен быть длинным. Если админский ключ не нужен, оставь поле пустым и снова нажми «Настроить».

**Обычный ключ** меняет на зарубежном сервере два файла внутри контейнера AmneziaWG: добавляет нового пользователя в конфиг (`/opt/amnezia/awg/awg0.conf` или `wg0.conf`) и его имя в `clientsTable`. Копия конфига до изменения лежит рядом, в файле `.relay-connect.bak`.

## Обслуживание

После настройки relay работает сам и переживает перезагрузку. Все команды ниже выполняются на RU-сервере под root.

| Задача | Команда |
| --- | --- |
| Статус relay | `systemctl status relay-connect@udp` |
| Последние 50 строк лога | `journalctl -u relay-connect@udp -n 50 --no-pager` |
| Куда пересылается | `cat /etc/relay-connect/udp.toml` |
| Слушает ли порт | `ss -lnup \| grep realm` |
| Перезапустить | `systemctl restart relay-connect@udp` |
| Жив ли IPv6 до зарубежного | `ping -6 -c 3 <IPv6 зарубежного>` |
| Идёт ли трафик клиентов | `tcpdump -ni any udp port <порт> -c 20` |

Для TCP-портов (например, если стоит Xray) везде замени `udp` на `tcp`.

**Если заблокировали IPv6 зарубежного сервера.** Хостеры обычно выдают целую подсеть /64, так что можно добавить другой адрес из неё или попросить новую у хостера. Затем впиши новый IPv6 в программу и снова нажми «Настроить». Клиентам ничего менять не надо: они по-прежнему ходят на RU-сервер.

**Если меняешь порт в Amnezia.** Снова нажми «Настроить», программа найдёт новый порт сама. После этого клиентские ключи нужно переделать заново.

**Удаление.** Кнопка «Удалить relay с RU-сервера» останавливает сервисы и удаляет realm, конфиги и настройки буферов. Правила фаервола остаются. Мост на зарубежном сервере, если он ставился, удаляется вручную: `systemctl disable --now relay-connect@bridge-udp relay-connect@bridge-tcp`.

## FAQ: проблемы и решения

Найди в таблицах текст красной или жёлтой строки из лога: таблицы идут по этапам работы программы. Если ничего не подошло, скопируй весь лог из окна: по нему проще всего разобраться.

### Подключение к серверам

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «неверный логин или пароль» | опечатка в пароле, либо вход по паролю или для root запрещён в sshd | введи пароль заново; через консоль хостера проверь в `/etc/ssh/sshd_config` строки `PermitRootLogin yes` и `PasswordAuthentication yes`, потом `systemctl restart ssh` |
| «не удалось подключиться по SSH: timed out» | неверный IP или порт, сервер выключен, порт закрыт фаерволом хостера | проверь адрес и SSH-порт в панели, попробуй зайти через PuTTY или `ssh root@IP` |
| «нужен пользователь root (сейчас uid=…)» | вход не под root | задай пароль root (`sudo passwd root`), разреши `PermitRootLogin yes` и входи как root |
| «нет systemd» | необычная ОС или контейнерная виртуализация | переустанови VPS на Ubuntu 22.04/24.04 или Debian 12 |
| ⚠ «Через RU-сервер не вышло… Пробую напрямую» | у RU-сервера нет IPv6, либо в его sshd выключен `AllowTcpForwarding`, либо sshd зарубежного не слушает IPv6 | на RU-сервере выполни `ping -6 -c 3 <IPv6 зарубежного>`; в `/etc/ssh/sshd_config` не должно быть `AllowTcpForwarding no` |
| «Не удалось достучаться до зарубежного сервера по IPv6…» | IPv6 не работает на одной из сторон, либо введён не тот адрес | зайди на зарубежный сервер через VNC-консоль хостера, выполни `ip -6 addr` и `ss -ltn \| grep :22`; там должны быть твой адрес и `[::]:22` |
| ⚠ «подключено напрямую. ВНИМАНИЕ…» | у твоего ПК есть IPv6, а путь через RU-сервер не сработал | само по себе не ошибка; дальше программа проверит IPv6-маршрут с RU-сервера |

### IPv6

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «… — это не IPv6-адрес» | адрес вставлен с маской `/64` или с лишними символами | убери `/64` и пробелы; квадратные скобки можно оставить |
| «… — не публичный (global) IPv6-адрес» | взят локальный адрес вида `fe80::…` | возьми адрес из вывода `ip -6 addr show scope global` или из панели хостера |
| «… — это адрес подсети, а не сервера» | в конце адреса потерялась цифра (`…::` вместо `…::2`); на такой адрес отвечает маршрутизатор хостера, поэтому ping проходит, а SSH и VPN нет | скопируй адрес целиком из `ip -6 addr show scope global` на зарубежном сервере |
| «На зарубежном сервере нет ни одного глобального IPv6-адреса» | IPv6 выдан хостером, но не настроен в системе, либо не выдан вообще | включи IPv6 в панели; если он там есть, спроси в поддержке, как прописать его в netplan |
| ⚠ «… нет среди адресов интерфейса» | опечатка или адрес от другого сервера | сверь со списком адресов в скобках и впиши правильный |
| «У RU-сервера нет IPv6-маршрута до зарубежного сервера» | у российского VPS нет IPv6 | включи IPv6 в панели или смени хостера; проверка: `ping -6 -c 3 google.com` на RU-сервере |
| ⚠ «ping по IPv6 не проходит» | часто просто запрещён ICMP | не критично, если дальше сквозная проверка прошла |

### Порты Amnezia

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «На зарубежном сервере нет docker» | Amnezia стоит не через приложение, а вручную | впиши порты в поле «Порты», например `51820/udp`; порт виден в клиентском конфиге в строке `Endpoint`, после двоеточия |
| «Не нашёл контейнеров Amnezia» | контейнеры остановлены | на зарубежном сервере `docker ps -a`, затем `docker start amnezia-awg`; или впиши порты вручную |
| «Не понял порт» | неверный формат | формат `порт/протокол` через запятую: `51820/udp, 443/tcp`; без протокола считается udp |
| «На RU-сервере уже заняты порты» | на RU-сервере этот порт уже слушает другая программа (в скобках её имя) | останови её, либо смени порт протокола в Amnezia и потом переделай ключи |
| ⚠ «… НЕ слушается по IPv6 — поставлю мост» | docker опубликовал порт только для IPv4 | ничего, программа поставит мост сама |

| «Не удалось скачать realm ни на сервере, ни на ПК» | GitHub недоступен с обеих сторон | скачай `realm-x86_64-unknown-linux-musl.tar.gz` версии v2.9.6 со страницы [релизов realm](https://github.com/zhboner/realm/releases) через другой VPN, распакуй и положи файл `realm` в `/usr/local/bin/realm` (`chmod +x`). Программа увидит его и качать не станет |
| «неподдерживаемая архитектура процессора» | сервер не x86_64 и не aarch64 | возьми обычный VPS на x86_64 |
| «сервис relay-connect@… не запустился» и лог ниже | realm не принял конфиг или не смог занять порт | причина написана в логе под сообщением; скопируй лог целиком, по нему видно, что не так |
| «команда упала (код N): …» | какая-то команда на сервере завершилась с ошибкой | в сообщении есть сама команда и вывод ошибки: чаще всего это фаервол или занятый apt (идёт автообновление); подожди пару минут и повтори |

### Сквозная проверка

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| ⚠ «тестовый UDP-пакет не дошёл до зарубежного сервера» | внешний фаервол в панели зарубежного хостера (например, Hetzner Cloud Firewall) или фильтр UDP по IPv6 у одного из хостеров | открой в панели хостера входящий UDP на порт Amnezia для IPv6 и нажми «Настроить» ещё раз; если не помогло, напиши в поддержку хостера |
| ⚠ «пропущена (нет tcpdump)» | на зарубежном сервере нет tcpdump и не вышло его поставить | не ошибка: просто подключись клиентом и проверь |
| ⚠ «TCP-соединение до […]:порт не установилось» | TCP-порт зарубежного сервера закрыт для IPv6 | то же, что для UDP: фаервол в панели хостера |

### Конфиг клиента

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «Ключ должен начинаться с vpn://» или «В конфиге нет строки Endpoint» | вставлено что-то другое или ключ обрезан при копировании | скопируй ключ заново целиком или открой файл кнопкой «Открыть файл…» |
| «В ключе не найден hostName» или «Старый адрес … не найден» | формат ключа необычный | впиши в поле «Старый адрес» заблокированный IPv4 зарубежного сервера |
| «… — это не IPv4-адрес» | поле «Новый адрес» пустое или с опечаткой | впиши IPv4 RU-сервера |

### Ключи

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «не запущен контейнер AmneziaWG» | на сервере нет протокола AmneziaWG или контейнер остановлен | `docker ps -a` на зарубежном сервере, затем `docker start amnezia-awg2` (или `amnezia-awg`); ключи программа выдаёт только для AmneziaWG |
| ⚠ «RU-сервер не пересылает порт …/udp» | relay ещё не настроен или настроен на другой порт | нажми «Настроить» на вкладке «Настройка»; ключ при этом уже создан и заработает после настройки |
| «AmneziaWG не принял нового пользователя — конфиг сервера возвращён как был» | ошибка при применении конфига | ничего не сломано; причина видна в журнале на вкладке «Ключи» |
| «На RU-сервере нет SSH-проброса на порт …» | SSH-проброс не включён | впиши порт в поле «SSH-проброс» (например 2222) и нажми «Настроить» |
| ⚠ «SSH-проброс на порт … не ответил» | порт закрыт фаерволом в панели RU-хостера или SSH зарубежного сервера слушает другой порт | открой TCP-порт проброса в панели RU-хостера; проверь SSH-порт зарубежного сервера на вкладке «Настройка» |
| Приложение Amnezia не может подключиться к серверу по админскому ключу | порт SSH-проброса закрыт снаружи | проверь с ПК: `ssh -p 2222 root@<IPv4 RU-сервера>` должен попросить пароль зарубежного сервера |

### Общие вопросы

**Всё настроилось, но клиент не подключается или нет интернета.** Иди по цепочке по порядку:

1. В клиенте импортирован именно преобразованный ключ, и в нём адрес RU-сервера.
2. Пакеты от клиента доходят до RU-сервера: на нём запусти `tcpdump -ni any udp port <порт> -c 20` и подключись. Если пусто, порт закрыт фаерволом в панели российского хостера.
3. Пакеты доходят до зарубежного сервера: та же команда там. Если пусто, смотри строку про тестовый UDP-пакет выше.
4. Если пакеты идут в обе стороны, а сайты не открываются, уменьши MTU в настройках подключения, например до 1280.

**Низкая скорость.** Скорость ограничена самым узким каналом в цепочке. Чаще всего это тариф RU-VPS (например, 100 Мбит/с) или дальний маршрут RU → DE. Помогает тариф с более широким каналом или дата-центр в Москве или Петербурге. Учти, что трафик считается дважды: входящий и исходящий на RU-сервере.

**Приложение Amnezia больше не управляет сервером, кнопки «Поделиться» нет.** Для управления приложение ходит по SSH на заблокированный IPv4, а у обычного ключа управления нет вообще. Создай на вкладке «Ключи» админский ключ и импортируй его в приложение: тогда оно управляет сервером через RU-сервер. Если нужен просто ключ для нового устройства, там же создай обычный ключ.

**Можно ли подключать несколько устройств и людей?** Да, все клиенты идут через один relay. Но каждому устройству нужен свой ключ: добавь пользователя в Amnezia и прогони его ключ через «Конфиг клиента». Если одним ключом одновременно пользуются два устройства, они выбивают друг друга: подключение то работает, то пропадает.

**Что будет, если заблокируют IPv4 российского сервера?** Российские адреса блокируют редко, но если такое случится, возьми другой RU-VPS и прогони настройку заново. Клиентские ключи потом переделай на новый адрес.

**Нужно ли что-то делать после перезагрузки серверов?** Нет. Сервисы стартуют сами, а Amnezia в docker поднимается как раньше.

## Безопасность и ограничения

RU-сервер видит только зашифрованные пакеты AmneziaWG. Ключей шифрования на нём нет, сайты, которые ты открываешь, с него не видны.

- **Пароли** используются только для SSH-подключения и никуда не записываются. После настройки стоит перейти на вход по SSH-ключу и выключить вход по паролю. Программа пока умеет только пароли, так что для повторной настройки его придётся временно включить.
- **Ключ хоста SSH** принимается автоматически, без сверки отпечатка. Запускай программу из домашней сети, а не из открытого Wi-Fi.
- **Российский хостер видит,** что сервер гоняет много UDP-трафика на зарубежный адрес. Протокол замаскирован, но у части хостеров VPN запрещён в правилах или фильтруется. Проверь правила до покупки.
- **IPv6 тоже могут заблокировать.** Схема работает, пока заблокирован только IPv4. Как сменить IPv6, см. раздел «Обслуживание».
- **Поддерживается** только Linux с systemd на x86_64 или aarch64. Вход нужен под root.
- **Программа пока не проверена на реальных серверах.** Первый запуск делай с включенным доступом в консоль хостера, и сначала жми «Проверить».
