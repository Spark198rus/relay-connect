# Relay Connect — документация и FAQ

Актуально на 15 ноября 2026.

## Что это и зачем

Relay Connect возвращает доступ к VPN на зарубежном сервере, у которого заблокирован IPv4. Клиенты подключаются к российскому VPS по IPv4, а тот пересылает трафик на IPv6 зарубежного сервера.

```
                 IPv4                     IPv6
 Клиент AmneziaWG ────► RU-сервер (realm) ──────► Зарубежный VPS ──────► Интернет
 телефон или ПК         IPv4 :порт → IPv6         AmneziaWG              выход из DE
 в России                                          IPv6 :порт
       │                                                ▲
       └──────── прямой путь на IPv4 заблокирован ──────┘ ✕
```

RU-сервер принимает клиентов по IPv4 и пересылает их пакеты на IPv6 зарубежного сервера на тот же порт. Заблокированный IPv4 зарубежного сервера больше не нужен.

- **Почему это работает.** Блокировка привязана к конкретному IPv4-адресу. Российский IPv4 не заблокирован, а IPv6 зарубежного сервера в списке блокировок обычно нет.
- **Что ставится.** На RU-сервер ставится realm, маленький пересыльщик TCP/UDP. Пакеты AmneziaWG он пересылает как есть и ничего не расшифровывает.
- **Почему не 3x-ui, как в видео.** Схема на VLESS требует перевести всех клиентов на другой протокол. Здесь AmneziaWG, ключи и протокол остаются прежними, в клиенте меняется только адрес сервера.
- **Почему не каскад из инструкции установщика.** В [CASCADE.md](https://github.com/bivlked/amneziawg-installer/blob/main/CASCADE.md) на RU-сервер ставится второй AmneziaWG, и трафик там расшифровывается. Здесь RU-сервер только пересылает зашифрованные пакеты.
- **Что нужно от тебя.** IPv4 российского сервера, IPv6 зарубежного и root-пароли от обоих. Всё остальное программа делает сама.

## Требования

Главное условие: IPv6 должен работать на обоих серверах. Без IPv6 на российском VPS схема не заработает.

| | Российский VPS (вход) | Зарубежный VPS (выход) |
| --- | --- | --- |
| IPv4 | нужен, к нему подключаются клиенты | заблокирован, не используется |
| IPv6 | нужен, через него идёт трафик на зарубежный | нужен, публичный (global) |
| Доступ | root и пароль по SSH | root и пароль по SSH |
| ОС | Linux с systemd: Ubuntu, Debian и похожие | Linux с systemd; чтобы программа сама поставила AmneziaWG — Ubuntu 24.04/26.04 или Debian 12/13 |
| AmneziaWG | не нужен | [amneziawg-installer](https://github.com/bivlked/amneziawg-installer) с IPv6 на сервере, Amnezia из приложения (docker) или ничего |
| Процессор | x86_64 или aarch64 (ARM) | x86_64 или aarch64, если понадобится мост |
| Ресурсы | хватит самого дешёвого тарифа, важнее канал и лимит трафика | как сейчас |

- **ПК, с которого запускаешь программу:** Windows 10 или 11. IPv6 на ПК не нужен: к зарубежному серверу программа ходит через российский.
- **AmneziaWG на зарубежном сервере** программа находит сама, подробнее в разделе «Подготовка зарубежного сервера».
- **При выборе российского VPS спроси у хостера про IPv6 до оплаты.** Многие выдают его только по запросу или за отдельную галочку в панели.

## Подготовка зарубежного сервера

Программа сама определяет, как на зарубежном сервере стоит AmneziaWG, и проверяет варианты в таком порядке:

| Что на сервере | Как программа это узнаёт | Что делает |
| --- | --- | --- |
| AmneziaWG от amneziawg-installer | есть `/etc/amnezia/amneziawg/awg0.conf` и `/root/awg/manage_amneziawg.sh` | берёт порт из `awg0.conf`, прописывает адрес RU-сервера в настройки установщика, ключи создаёт через `manage_amneziawg.sh` |
| Amnezia, поставленная приложением Amnezia | запущены контейнеры `amnezia-*` (`docker ps`) | берёт опубликованные порты контейнеров, новые ключи и админский ключ собирает сама |
| незаконченная установка amneziawg-installer | есть `/root/awg/setup_state` | предлагает продолжить установку |
| ничего | ни того, ни другого | предлагает поставить AmneziaWG скриптом amneziawg-installer |

Если на сервере есть и amneziawg-installer, и старые контейнеры Amnezia, программа работает с установщиком. Порты контейнеров тогда пробрасываются, только если вписать их в поле «Порты».

### Установка AmneziaWG программой

Если AmneziaWG на сервере нет, «Настроить» останавливается до любых изменений на обоих серверах и спрашивает, ставить ли его. В окне вопроса перечислено, что произойдёт с сервером. После «Да» программа:

1. Проверяет ОС зарубежного сервера. Установщик поддерживает Ubuntu 24.04/26.04 и Debian 12/13, на другой ОС программа ставить не станет.
2. Скачивает последний выпуск `install_amneziawg.sh` с GitHub в `/root/install_amneziawg.sh`. Если сам сервер GitHub не видит, файл качается на ПК и заливается по SFTP. Учти, что по ходу работы установщик ещё скачивает свои скрипты с GitHub.
3. Запускает его в фоне: `bash /root/install_amneziawg.sh --yes --no-color --allow-ipv6 --keep-packages --endpoint=<IPv4 RU-сервера>`.
   - `--allow-ipv6`: без него установщик выключит IPv6, а relay ходит на сервер именно по IPv6;
   - `--keep-packages`: не удалять snapd, cloud-init и прочее, что уже стоит на сервере;
   - `--endpoint`: ключи клиентов сразу будут вести на RU-сервер.
4. Показывает в журнале строки лога установщика. Установщик два раза перезагружает сервер. Программа ждёт, пока сервер вернётся (до 15 минут на каждую перезагрузку), подключается заново через RU-сервер и запускает установщик ещё раз с теми же флагами: так он продолжает с нужного шага.
5. Когда установка закончена, продолжает обычную настройку relay.

Всё занимает 10–30 минут, большую часть времени уходит на обновление пакетов. Не закрывай программу, а на Android не сворачивай приложение. Установщик обновляет систему, включает фаервол UFW (входящие подключения закрыты, кроме SSH и порта AmneziaWG) и ставит Fail2Ban. Если на сервере работает что-то ещё, UFW может закрыть к нему доступ.

Если установка прервалась (закрыл программу, пропала связь, установщик остановился с ошибкой), нажми «Настроить» ещё раз: программа предложит продолжить, и установщик пойдёт с того же шага. Вывод установщика лежит в `/root/relay-connect-awg-install.out`, его собственный лог в `/root/awg/install_amneziawg.log`.

### Если amneziawg-installer ставили сами

По умолчанию amneziawg-installer выключает IPv6 на сервере (`disable_ipv6 = 1` в `/etc/sysctl.d/99-amneziawg-security.conf`). Relay ходит на зарубежный сервер именно по IPv6, поэтому IPv6 должен остаться включённым.

**Новая установка вручную.** Запускай установщик с флагом `--allow-ipv6`:

```bash
bash install_amneziawg.sh --allow-ipv6
```

Порт, подсеть и остальные флаги выбирай как обычно. Программа сама прочитает порт из конфига.

**Сервер уже поставлен без `--allow-ipv6`.** Программа зайти на него не сможет: по IPv6 он недоступен, а IPv4 заблокирован. Зайди через VNC-консоль хостера или по SSH на IPv4 из сети, где адрес не заблокирован, и выполни:

```bash
sed -i -E 's/^(net\.ipv6\.conf\.(all|default|lo)\.disable_ipv6 *= *)1/\10/' /etc/sysctl.d/99-amneziawg-*.conf
sed -i 's/^export DISABLE_IPV6=.*/export DISABLE_IPV6=0/' /root/awg/awgsetup_cfg.init
reboot
```

Первая команда убирает выключение IPv6 из sysctl. Вторая меняет настройку установщика, чтобы его повторный запуск не выключил IPv6 снова. После перезагрузки `ip -6 addr show scope global` должен показать IPv6-адрес, а `ss -lnu | grep <порт>` строку `[::]:<порт>`.

Если IPv6 включён сейчас, но в sysctl осталось `disable_ipv6 = 1` (например, его включили вручную командой `sysctl -w`), «Проверить» покажет предупреждение, а «Настроить» поправит файлы сама.

## Установка и запуск

Программа есть для Windows, macOS, Linux и Android, функции везде одинаковые. На Windows проще всего взять готовый `RelayConnect.exe` из папки `dist`: устанавливать ничего не нужно.

| Система | Файл | Как запустить |
| --- | --- | --- |
| Windows 10/11 | `RelayConnect-windows.exe` (или `dist\RelayConnect.exe`) | двойной клик |
| macOS, Apple Silicon | `RelayConnect-macos-arm64.zip` | распаковать, правый клик по `RelayConnect.app` → «Открыть»; если macOS не даёт: `xattr -dr com.apple.quarantine RelayConnect.app` |
| macOS, Intel | исходники | `pip3 install -r requirements.txt`, затем `python3 app.py` |
| Linux x86_64 | `RelayConnect-linux-x86_64.tar.gz` | `tar xzf RelayConnect-linux-x86_64.tar.gz && ./RelayConnect`, нужен графический сеанс |
| Android 7+, 64-bit | `RelayConnect-android.apk` | скопировать на телефон, открыть, разрешить установку из неизвестных источников |

Все файлы собирает GitHub Actions: при каждом пуше они появляются в артефактах запуска, а при пуше тега `v1.0.0` в релизе. Вручную настольные версии собираются скриптом `build.bat` (Windows) или `build.sh` (macOS, Linux).

**Особенности Android-версии.** Разделы «Настройка», «Ключи» и «Переделать» переключаются кнопками сверху. Ключ клиента вставляется текстом из буфера обмена, открыть файл нельзя. Результат копируется кнопкой «Копировать» или отправляется кнопкой «Поделиться». Пока идёт настройка, не сворачивай приложение: Android может оборвать SSH-соединение фонового приложения.

Для сборки и запуска из исходников нужен Python 3.10 или новее с tkinter. На Ubuntu и Debian его ставит `sudo apt install python3-tk`, на macOS tkinter уже входит в Python с python.org.

- **Windows SmartScreen** может предупредить о неизвестном издателе: файл не подписан. Нажми «Подробнее» → «Выполнить в любом случае».
- **Антивирус** иногда ругается на файлы, собранные PyInstaller. Если не доверяешь .exe, запускай `python app.py`: код тот же.
- **Настройки формы** (адреса, порты, логины) запоминаются в `%APPDATA%\relay-connect\settings.json`. Пароли не сохраняются нигде.

## Пошаговая инструкция

Настройка занимает три кнопки: «Проверить», «Настроить» и кнопку получения ключа на вкладке «Ключи». В логе зелёные строки ✔ означают успех, жёлтые ⚠ предупреждение, красные ✖ ошибку.

1. **Узнай адреса.** IPv4 российского сервера и IPv6 зарубежного есть в панели хостера. Ещё IPv6 можно посмотреть на самом сервере командой `ip -6 addr show scope global`: нужен адрес после `inet6`, без `/64`.
2. **Заполни вкладку «Настройка».** Адреса, SSH-порты (обычно 22), логин `root` и пароли. Поле «Порты» оставь пустым: программа возьмёт порт AmneziaWG из `awg0.conf` (amneziawg-installer) или из `docker ps` (Amnezia в docker).
3. **Нажми «1. Проверить».** На серверах ничего не меняется. Программа проверит пароли, IPv6 на обоих серверах, AmneziaWG и его порт и то, что на RU-сервере этот порт свободен. Если AmneziaWG на зарубежном сервере нет, будет жёлтая строка: его предложит поставить «Настроить». Пока в логе есть красные строки, дальше не иди: смотри FAQ ниже.
4. **Нажми «2. Настроить».** Занимает от 30 секунд до пары минут. Программа поставит relay, прогонит тестовый пакет насквозь, а для amneziawg-installer ещё пропишет адрес RU-сервера в его настройки и перевыпустит файлы клиентов. В конце будет окно «Готово» с новым адресом для клиентов. Если AmneziaWG нет, сначала появится вопрос, ставить ли его (раздел «Установка AmneziaWG программой»): установка займёт 10–30 минут.
5. **Возьми ключи клиентов.**
   - amneziawg-installer: на вкладке «Ключи» впиши имя клиента (список имён есть в журнале «Настроить» или в `bash /root/awg/manage_amneziawg.sh list`) и нажми «Показать ключ существующего». Ключ `vpn://…` импортируется в Amnezia VPN, файл `.conf` в AmneziaWG.
   - Amnezia в docker: старые ключи возьми в приложении Amnezia («Поделиться») и поменяй в них адрес на вкладке «Конфиг клиента». Новые создавай на вкладке «Ключи».
6. **Импортируй ключ на устройстве как новое подключение** и подключись. Старое подключение после проверки удали. Это тот же клиент с теми же ключами шифрования, поэтому на двух устройствах одновременно он не работает: устройства будут выбивать друг друга. Для нового устройства создай отдельного клиента кнопкой «Создать нового клиента».

Проверка, что трафик идёт через зарубежный сервер: после подключения открой любой сайт «мой IP». Должен показаться немецкий адрес, а не адрес RU-сервера.

Вкладка «Конфиг клиента» меняет адрес в `vpn://…` или `.conf`, который уже на руках, на IPv4 RU-сервера. Для Amnezia в docker это единственный способ сохранить старые ключи. Для amneziawg-installer перевыпущенный ключ с вкладки «Ключи» надёжнее: в режимах раздельной маршрутизации установщик исключает адрес сервера из `AllowedIPs`, и при перевыпуске там стоит уже адрес RU-сервера, а «Конфиг клиента» меняет только `Endpoint`.

## Выдача ключей

Ключи выдаются на вкладке «Ключи». Программа заходит на зарубежный сервер через RU-сервер (заблокированный IPv4 ей не нужен), сама определяет, как там стоит AmneziaWG, и сразу кладёт в ключ адрес RU-сервера. Данные серверов берутся с вкладки «Настройка».

| Кнопка | amneziawg-installer | Amnezia в docker |
| --- | --- | --- |
| «Создать нового клиента» | `manage_amneziawg.sh add <имя>` | программа дописывает пользователя в конфиг AmneziaWG контейнера и собирает ключ |
| «Показать ключ существующего» | читает `/root/awg/<имя>.conf` и `<имя>.vpnuri`, ничего не меняет | не работает: сервер не хранит ключи пользователей |
| «Создать админский ключ» | не работает: таким сервером приложение Amnezia управлять не умеет | ключ полного доступа для приложения Amnezia |

Ключ показывается в двух видах: `vpn://…` для приложения Amnezia VPN («Добавить» → «Вставить ключ») и `.conf` для приложения AmneziaWG.

### amneziawg-installer

Клиентов создаёт сам установщик. Ссылку `vpn://` он создаёт, только если на сервере есть perl с модулем Compress::Zlib; без него будет только `.conf`.

**Имя клиента** установщик принимает только из латиницы, цифр, `-` и `_`, до 63 символов. Кириллицу программа переводит в латиницу, пробелы заменяет на `_`: «Телефон мамы» станет `Telefon_mamy`.

**Почему ключи сразу с адресом RU-сервера.** При «Настроить» программа пишет IPv4 RU-сервера в `AWG_ENDPOINT` в `/root/awg/awgsetup_cfg.init`. Это штатная настройка установщика (то же делает его флаг `--endpoint`): все ключи, которые он выдаёт или перевыпускает, ведут на этот адрес. Поэтому и клиенты, созданные прямо на сервере командой `bash /root/awg/manage_amneziawg.sh add <имя>`, сразу работают через relay. Если «Настроить» ещё не нажимали, кнопки вкладки «Ключи» пропишут адрес сами.

### Amnezia в docker

| | Обычный ключ | Админский ключ |
| --- | --- | --- |
| Для чего | подключить новое устройство | управлять сервером из приложения Amnezia: создавать пользователей, делиться ключами |
| Что делает программа | добавляет нового пользователя в AmneziaWG в контейнере, его имя видно в списке пользователей Amnezia | собирает ключ полного доступа с SSH-доступом к серверу через RU-сервер |
| Адрес внутри | IPv4 RU-сервера и порт AmneziaWG | IPv4 RU-сервера и порт SSH-проброса (например 2222) |
| Формат | `vpn://…` одной строкой или файл `.conf` | `vpn://…` |
| Можно пересылать | да, это обычный ключ на одно устройство | нет: внутри root-пароль зарубежного сервера |

**Обычный ключ.** Впиши имя пользователя (здесь можно и кириллицей, например «Телефон мамы») и нажми «Создать нового клиента». Перед изменением программа сохраняет копию конфига сервера, и если AmneziaWG не примет нового пользователя, всё вернётся как было.

**Админский ключ.** Сначала на вкладке «Настройка» впиши порт в поле «SSH-проброс» (например 2222) и нажми «Настроить»: RU-сервер начнёт пересылать этот порт на SSH зарубежного сервера. Потом нажми «Создать админский ключ» и импортируй его в своё приложение Amnezia. После этого приложение снова управляет сервером, и ключи, которые оно создаёт через «Поделиться», сразу будут с адресом RU-сервера. При первом подключении приложение само создаст себе пользователя на сервере, так делает Amnezia с любым админским ключом.

В админский ключ попадает только протокол AmneziaWG. Другие протоколы на сервере, если они есть, приложение через такой ключ не увидит.

## Что программа меняет на серверах

На RU-сервер ставится relay. Уже установленный AmneziaWG на зарубежном сервере программа не переустанавливает: она открывает порт, при необходимости ставит мост, а для amneziawg-installer меняет две его настройки. Если AmneziaWG нет, программа с твоего согласия ставит его установщиком, тот меняет на сервере многое сам (раздел «Установка AmneziaWG программой»).

| Сервер | Что | Где | Зачем |
| --- | --- | --- | --- |
| RU | realm v2.9.6 | `/usr/local/bin/realm` | пересыльщик TCP/UDP |
| RU | конфиги relay | `/etc/relay-connect/udp.toml`, `tcp.toml` | какие порты куда пересылать |
| RU | сервисы `relay-connect@udp`, `relay-connect@tcp` | `/etc/systemd/system/relay-connect@.service` | автозапуск и перезапуск через 3 секунды при падении |
| RU | буферы UDP | `/etc/sysctl.d/99-relay-connect.conf` | меньше потерь на быстром трафике |
| RU | правила фаервола IPv4 | ufw, firewalld или iptables | открыть порты для клиентов, только если фаервол включён |
| Зарубежный | AmneziaWG, если его не было | `/root/install_amneziawg.sh`, всё остальное ставит сам установщик | только с твоего согласия |
| Зарубежный | адрес в ключах клиентов (amneziawg-installer) | `AWG_ENDPOINT` в `/root/awg/awgsetup_cfg.init`, копия до изменения в `awgsetup_cfg.init.relay-connect.bak` | ключи, которые выдаёт установщик, ведут на RU-сервер |
| Зарубежный | файлы клиентов (amneziawg-installer) | `/root/awg/<имя>.conf`, `.vpnuri`, `.png` | перевыпускаются через `manage_amneziawg.sh regen` с адресом RU-сервера |
| Зарубежный | новый пользователь (Amnezia в docker) | конфиг AmneziaWG в контейнере и `clientsTable`, копия до изменения `awg0.conf.relay-connect.bak` | только при «Создать нового клиента» |
| Зарубежный | IPv6 после перезагрузки (amneziawg-installer) | `disable_ipv6 = 1` → `0` в `/etc/sysctl.d/99-amneziawg-*.conf`, `DISABLE_IPV6=0` в `awgsetup_cfg.init` | только если установщик выключал IPv6: иначе relay перестанет работать после перезагрузки |
| Зарубежный | правила фаервола IPv6 | ufw, firewalld или ip6tables | пустить трафик на порт AmneziaWG по IPv6; правило установщика в UFW уже есть, его программа не трогает |
| Зарубежный | мост `relay-connect@bridge-udp` | те же пути, что на RU | только если AmneziaWG не слушает IPv6: передаёт `[IPv6]:порт` на `127.0.0.1:порт` |
| Зарубежный | tcpdump | через apt | для сквозной проверки UDP, если его не было |

Сервисы relay работают не от root, а от временного системного пользователя (DynamicUser). У них есть только право занимать порты. Повторное нажатие «Настроить» безопасно: конфиги перезаписываются, дубли правил не создаются.

**NAT AmneziaWG программа не трогает.** Фаервол firewalld она не перезагружает: такая перезагрузка сбрасывает правила, добавленные в обход него (например, NAT из `PostUp` AmneziaWG). Если фаервол настроен напрямую через iptables или ip6tables, правила программы восстанавливает после перезагрузки отдельный сервис `relay-connect-fw-v4` или `relay-connect-fw-v6`. Он добавляет только свои правила из `/etc/relay-connect/`, чужие правила никуда не сохраняются.

**SSH-проброс** (если в поле «SSH-проброс» указан порт, например 2222) добавляет на RU-сервере ещё одну пересылку: TCP-порт ведёт на SSH зарубежного сервера. Так к зарубежному серверу можно зайти, пока его IPv4 заблокирован: `ssh -p 2222 root@<IPv4 RU-сервера>`, а там уже `bash /root/awg/manage_amneziawg.sh …`. Для Amnezia в docker через этот порт работает админский ключ. По умолчанию поле пустое. Учти две вещи:

- через этот порт к SSH зарубежного сервера может постучаться кто угодно, поэтому root-пароль должен быть длинным, а лучше вход по ключу;
- для зарубежного сервера все такие подключения приходят с IPv6 RU-сервера. Если кто-то начнёт подбирать пароль, Fail2Ban (его ставит amneziawg-installer) забанит адрес RU-сервера, и на какое-то время программа тоже не сможет зайти на зарубежный сервер. Сам VPN бан не задевает: он касается только SSH. Если проброс не нужен, оставь поле пустым и снова нажми «Настроить».

**«Создать нового клиента»** для amneziawg-installer работает так же, как `manage_amneziawg.sh add` на самом сервере: установщик сам добавляет клиента в `awg0.conf`, применяет конфиг и делает резервные копии.

## Обслуживание

После настройки relay работает сам и переживает перезагрузку. Все команды ниже выполняются на RU-сервере под root.

| Задача | Команда |
| --- | --- |
| Статус relay | `systemctl status relay-connect@udp` |
| Последние 50 строк лога | `journalctl -u relay-connect@udp -n 50 --no-pager` |
| Куда пересылается | `cat /etc/relay-connect/udp.toml` |
| Слушает ли порт | `ss -lnup \| grep realm` |
| Перезапустить | `systemctl restart relay-connect@udp` |
| Жив ли IPv6 до зарубежного | `ping -6 -c 3 <IPv6 зарубежного>` |
| Идёт ли трафик клиентов | `tcpdump -ni any udp port <порт> -c 20` |

Для TCP-портов (например, если стоит Xray) везде замени `udp` на `tcp`.

**Если заблокировали IPv6 зарубежного сервера.** Хостеры обычно выдают целую подсеть /64, так что можно добавить другой адрес из неё или попросить новую у хостера. Затем впиши новый IPv6 в программу и снова нажми «Настроить». Клиентам ничего менять не надо: они по-прежнему ходят на RU-сервер.

**Если меняешь порт AmneziaWG** (`bash /root/awg/manage_amneziawg.sh port <номер>` или в приложении Amnezia). amneziawg-installer сам перевыпустит клиентов. Затем снова нажми «Настроить»: программа возьмёт новый порт и перенастроит relay. Ключи клиентов возьми заново на вкладке «Ключи».

**Если меняешь RU-сервер.** Нажми «Настроить» с новым IPv4: для amneziawg-installer программа пропишет его в `AWG_ENDPOINT` и перевыпустит клиентов, для Amnezia в docker поменяй адрес в ключах на вкладке «Конфиг клиента». Старый relay удали кнопкой «Удалить relay с RU-сервера», пока в форме ещё старый адрес.

**Удаление.** Кнопка «Удалить relay с RU-сервера» останавливает сервисы и удаляет realm, конфиги и настройки буферов. Правила фаервола остаются. На зарубежном сервере вручную:

- мост, если он ставился: `systemctl disable --now relay-connect@bridge-udp relay-connect@bridge-tcp`;
- для amneziawg-installer вернуть в ключи клиентов прямой адрес сервера (когда его IPv4 разблокируют): `sed -i "s/^export AWG_ENDPOINT=.*/export AWG_ENDPOINT=''/" /root/awg/awgsetup_cfg.init`, затем `bash /root/awg/manage_amneziawg.sh regen`. Прежнее значение есть в `/root/awg/awgsetup_cfg.init.relay-connect.bak`.

## FAQ: проблемы и решения

Найди в таблицах текст красной или жёлтой строки из лога: таблицы идут по этапам работы программы. Если ничего не подошло, скопируй весь лог из окна: по нему проще всего разобраться.

### Подключение к серверам

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «неверный логин или пароль» | опечатка в пароле, либо вход по паролю или для root запрещён в sshd | введи пароль заново; через консоль хостера проверь в `/etc/ssh/sshd_config` строки `PermitRootLogin yes` и `PasswordAuthentication yes`, потом `systemctl restart ssh` |
| «не удалось подключиться по SSH: timed out» | неверный IP или порт, сервер выключен, порт закрыт фаерволом хостера | проверь адрес и SSH-порт в панели, попробуй зайти через PuTTY или `ssh root@IP` |
| «нужен пользователь root (сейчас uid=…)» | вход не под root | задай пароль root (`sudo passwd root`), разреши `PermitRootLogin yes` и входи как root |
| «нет systemd» | необычная ОС или контейнерная виртуализация | переустанови VPS на Ubuntu 22.04/24.04 или Debian 12 |
| ⚠ «Через RU-сервер не вышло… Пробую напрямую» | у RU-сервера нет IPv6, либо в его sshd выключен `AllowTcpForwarding`, либо sshd зарубежного не слушает IPv6 | на RU-сервере выполни `ping -6 -c 3 <IPv6 зарубежного>`; в `/etc/ssh/sshd_config` не должно быть `AllowTcpForwarding no` |
| «Не удалось достучаться до зарубежного сервера по IPv6…» | IPv6 не работает на одной из сторон, либо введён не тот адрес. Чаще всего amneziawg-installer поставлен без `--allow-ipv6` и выключил IPv6 | зайди на зарубежный сервер через VNC-консоль хостера, выполни `ip -6 addr` и `ss -ltn \| grep :22`; там должны быть твой адрес и `[::]:22`. Если адреса нет, смотри «Подготовка зарубежного сервера» |
| ⚠ «подключено напрямую. ВНИМАНИЕ…» | у твоего ПК есть IPv6, а путь через RU-сервер не сработал | само по себе не ошибка; дальше программа проверит IPv6-маршрут с RU-сервера |

### IPv6

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| «… — это не IPv6-адрес» | адрес вставлен с маской `/64` или с лишними символами | убери `/64` и пробелы; квадратные скобки можно оставить |
| «… — не публичный (global) IPv6-адрес» | взят локальный адрес вида `fe80::…` | возьми адрес из вывода `ip -6 addr show scope global` или из панели хостера |
| «… — это адрес подсети, а не сервера» | в конце адреса потерялась цифра (`…::` вместо `…::2`); на такой адрес отвечает маршрутизатор хостера, поэтому ping проходит, а SSH и VPN нет | скопируй адрес целиком из `ip -6 addr show scope global` на зарубежном сервере |
| «На зарубежном сервере нет ни одного глобального IPv6-адреса» | IPv6 выдан хостером, но не настроен в системе, либо не выдан вообще | включи IPv6 в панели; если он там есть, спроси в поддержке, как прописать его в netplan |
| ⚠ «IPv6 выключится после перезагрузки» | в sysctl осталось `disable_ipv6 = 1` от установщика | ничего, «Настроить» поправит; если только проверяешь, учти, что после перезагрузки сервер пропадёт до этой правки |
| ⚠ «… нет среди адресов интерфейса» | опечатка или адрес от другого сервера | сверь со списком адресов в скобках и впиши правильный |
| «У RU-сервера нет IPv6-маршрута до зарубежного сервера» | у российского VPS нет IPv6 | включи IPv6 в панели или смени хостера; проверка: `ping -6 -c 3 google.com` на RU-сервере |
| ⚠ «ping по IPv6 не проходит» | часто просто запрещён ICMP | не критично, если дальше сквозная проверка прошла |

| «Не нашёл ListenPort» | конфиг сервера правили вручную | верни строку `ListenPort = <порт>` в `awg0.conf` или впиши порт в поле «Порты» |
| ⚠ «Порт AmneziaWG … не входит в список портов» | в поле «Порты» вписаны порты без порта AmneziaWG | очисти поле «Порты»; иначе адрес в ключах программа не меняет |
| «Не понял порт» | неверный формат | формат `порт/протокол` через запятую: `39743/udp`; без протокола считается udp |

### Сквозная проверка

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| ⚠ «тестовый UDP-пакет не дошёл до зарубежного сервера» | внешний фаервол в панели зарубежного хостера (например, Hetzner Cloud Firewall) или фильтр UDP по IPv6 у одного из хостеров | открой в панели хостера входящий UDP на порт AmneziaWG для IPv6 и нажми «Настроить» ещё раз; если не помогло, напиши в поддержку хостера |

| ⚠ «В файле … адрес …, а не <IPv4 RU>» | файл клиента не перевыпустился | программа сама поменяла адрес в выданном ключе; файл на сервере перевыпусти: `bash /root/awg/manage_amneziawg.sh regen <имя>` |
| «не запущен контейнер AmneziaWG» | Amnezia в docker: на сервере нет протокола AmneziaWG или контейнер остановлен | `docker ps -a` на зарубежном сервере, затем `docker start amnezia-awg2` (или `amnezia-awg`); ключи программа выдаёт только для AmneziaWG |
| «AmneziaWG не принял нового пользователя — конфиг сервера возвращён как был» | Amnezia в docker: ошибка при применении конфига | ничего не сломано; причина видна в журнале на вкладке «Ключи» |
| «Amnezia в docker не хранит на сервере ключи пользователей» | «Показать ключ существующего» нажата для Amnezia в docker | возьми ключ в приложении Amnezia («Поделиться») и поменяй адрес на вкладке «Конфиг клиента» |
| «Админский ключ работает только с Amnezia, поставленной приложением» | сервер поставлен amneziawg-installer | клиентов создавай кнопкой «Создать нового клиента»; управлять сервером можно по SSH через SSH-проброс |
| «На RU-сервере нет SSH-проброса на порт …» | для админского ключа не включён SSH-проброс | впиши порт в поле «SSH-проброс» (например 2222) и нажми «Настроить» |
| Приложение Amnezia не может подключиться к серверу по админскому ключу | порт SSH-проброса закрыт снаружи | проверь с ПК: `ssh -p 2222 root@<IPv4 RU-сервера>` должен попросить пароль зарубежного сервера |
| ⚠ «Проверка SSH-проброса: … не пришёл ответ SSH» | порт закрыт фаерволом в панели RU-хостера или SSH зарубежного сервера слушает другой порт | открой TCP-порт проброса в панели RU-хостера; проверь SSH-порт зарубежного сервера на вкладке «Настройка» |

### Общие вопросы

**Всё настроилось, но клиент не подключается или нет интернета.** Иди по цепочке по порядку:

1. В клиенте импортирован новый ключ, и в нём адрес RU-сервера.
2. Пакеты от клиента доходят до RU-сервера: на нём запусти `tcpdump -ni any udp port <порт> -c 20` и подключись. Если пусто, порт закрыт фаерволом в панели российского хостера.
3. Пакеты доходят до зарубежного сервера: та же команда там. Если пусто, смотри строку про тестовый UDP-пакет выше.
4. Если пакеты идут в обе стороны, а сайты не открываются, уменьши MTU в настройках подключения, например до 1280.

**Низкая скорость.** Скорость ограничена самым узким каналом в цепочке. Чаще всего это тариф RU-VPS (например, 100 Мбит/с) или дальний маршрут RU → DE. Помогает тариф с более широким каналом или дата-центр в Москве или Петербурге. Учти, что трафик считается дважды: входящий и исходящий на RU-сервере.

**Как управлять зарубежным сервером, пока его IPv4 заблокирован?** Клиентов создаёт вкладка «Ключи». Для остального включи SSH-проброс и заходи через RU-сервер: `ssh -p 2222 root@<IPv4 RU-сервера>` (для amneziawg-installer там `manage_amneziawg.sh list`, `remove`, `stats`). Для Amnezia в docker можно взять админский ключ, и приложение Amnezia снова будет управлять сервером.

**Можно ли подключать несколько устройств и людей?** Да, все клиенты идут через один relay. Но каждому устройству нужен свой ключ: создай клиента на вкладке «Ключи». Если одним ключом одновременно пользуются два устройства, они выбивают друг друга: подключение то работает, то пропадает.

**Что будет, если заблокируют IPv4 российского сервера?** Российские адреса блокируют редко, но если такое случится, возьми другой RU-VPS и прогони настройку заново. Для amneziawg-installer программа перевыпустит ключи с новым адресом, их останется раздать на устройства; для Amnezia в docker поменяй адрес в ключах на вкладке «Конфиг клиента».

**Нужно ли что-то делать после перезагрузки серверов?** Нет. Сервисы стартуют сами, AmneziaWG поднимается как раньше. IPv6 на зарубежном сервере тоже остаётся: если установщик его выключал, «Настроить» это исправила.

**Можно ли выдавать ключи прямо на сервере, без программы?** Для amneziawg-installer да: после «Настроить» `bash /root/awg/manage_amneziawg.sh add <имя>` на зарубежном сервере сразу создаёт ключ с адресом RU-сервера. Для Amnezia в docker — через приложение Amnezia с админским ключом.

## Безопасность и ограничения

RU-сервер видит только зашифрованные пакеты AmneziaWG. Ключей шифрования на нём нет, сайты, которые ты открываешь, с него не видны.

- **Пароли** используются только для SSH-подключения и никуда не записываются. После настройки стоит перейти на вход по SSH-ключу и выключить вход по паролю. Программа пока умеет только пароли, так что для повторной настройки его придётся временно включить.
- **Установщик AmneziaWG** программа берёт из последнего выпуска [amneziawg-installer](https://github.com/bivlked/amneziawg-installer/releases) и запускает под root. Ставит его, только если ты согласился в окне вопроса.
- **Ключ хоста SSH** принимается автоматически, без сверки отпечатка. Запускай программу из домашней сети, а не из открытого Wi-Fi.
- **Российский хостер видит,** что сервер гоняет много UDP-трафика на зарубежный адрес. Протокол замаскирован, но у части хостеров VPN запрещён в правилах или фильтруется. Проверь правила до покупки.
- **IPv6 тоже могут заблокировать.** Схема работает, пока заблокирован только IPv4. Как сменить IPv6, см. раздел «Обслуживание».
- **Поддерживается** только Linux с systemd на x86_64 или aarch64. Вход нужен под root.
- **Программа пока не проверена на реальных серверах.** Первый запуск делай с включенным доступом в консоль хостера, и сначала жми «Проверить».
